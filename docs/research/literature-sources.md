# Literature sources for AI/ML gap discovery

**Decision (recommendation, 27 September 2026):** use OpenAlex as the default discovery and citation-graph index; reconcile records and check post-publication updates through Crossref; query arXiv directly for recent ML preprints and version status. Offer Semantic Scholar as an optional recommendation/enrichment source after its API license is confirmed for the product’s deployment and intended use. Treat all sources as search coverage, not proof that a research gap is novel. A candidate gap should remain provisional until a researcher searches its concepts, follows references/citations, and inspects the cited papers.

## Full-text and grounding policy

Keep the catalog separate from document rights. OpenAlex now offers cached PDFs and GROBID TEI for 50M+ works, metered per download; it explicitly says the PDFs retain their original copyright and OpenAlex grants no extra rights. Its `best_oa_location.license` and per-location license fields can guide filtering, but null, `other-oa`, or publisher-specific values do not establish a reusable license. [OpenAlex full-text terms and workflow](https://help.openalex.org/access/fulltext/) For routine processing, accept a full text only when the specific copy has a verified license compatible with the action (fetch, retain, quote, embed, or redistribute). Otherwise keep bibliographic metadata and link users to the source/publisher; let the researcher open the document under their own access. Do not persist PDFs, extracted passages, or embeddings by default until storage and downstream AI-provider use are covered by the applicable license/terms.

For every generated claim in gap discovery or planning, preserve a source record with DOI/arXiv ID, provider IDs, title, version/date, source URL, retrieval time, and evidence locator (page/section/paragraph or stable text span). Display short quoted evidence with context and link to the paper. Ground claims against the version actually retrieved; abstracts support only abstract-level claims. Ask the researcher to validate the gap and proposed question. A model’s missing search result cannot establish absence or novelty.

## Identity, freshness, and outages

Use DOI as the preferred work-level join key after normalization; retain arXiv IDs and every provider’s record ID as aliases. Where DOI is absent, match on normalized title plus author and year, keep the match confidence and candidate records, and require review for ambiguous matches. Preserve preprint and journal versions as related manifestations, not automatically as duplicate text: record version/DOI relationships and compare before collapsing. Do not merge solely on title or let a provider’s deduplication erase version history.

Cache source responses with source, query, fetched-at, and update/version timestamps. Refresh source-specific corrections and statuses before presenting a gap as actionable. Put each connector behind an adapter with bounded retries, `Retry-After`/rate-header handling where available, and circuit breaking. On source failure, show which sources ran and their freshness; reuse cached results as stale and label them. If a source is unavailable or a query fails, mark coverage incomplete and suppress any “no prior work found” conclusion. Do not silently substitute provider data as if the failed source had searched successfully.

## Facts vs. product decisions; validation gates

The access limits, data fields, and reuse distinctions above are facts stated by providers in the linked documentation (checked 27 September 2026). The source order, rights gate, identity rules, and UI behavior are recommendations for this research workspace, not provider guarantees or legal advice.

Before implementation is considered ready, validate: (1) query recall/precision on a researcher-curated AI/ML seed set, including conference proceedings, non-English records, recent preprints, and known DOI/arXiv duplicates; (2) actual identifier and version links across providers; (3) Crossref/Retraction Watch signal freshness and false/missing update cases; (4) rights display and permitted storage/LLM processing for each accepted full-text route; (5) API credentials, quotas, costs, and terms for expected per-user and background workloads, especially Semantic Scholar expansion; and (6) outage behavior, stale labels, and incomplete-search messaging. No provider’s corpus is complete, no topic classifier is authoritative, and no API SLA is assumed here.
