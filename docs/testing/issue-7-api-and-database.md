Put only `TEST_DATABASE_URL` in ignored root `.env.test.local`. Use a **disposable Neon branch**, a direct/non-pooler connection and a role that can create/drop schemas. The fixture creates a random `test_projects_<UUID>` schema, applies migrations, signs up synthetic `example.test` accounts through Better Auth, and drops only that generated schema. A terminated process can leave a generated schema; an operator may remove such schemas from the disposable branch or discard that branch.

`pnpm run check-types` verifies every workspace including the unchanged native scaffold. `pnpm exec biome check <touched files>` is non-mutating; `pnpm run check:readonly` checks the whole repository and also reports existing starter lint findings. Biome excludes generated `src/env.ts` Varlock declarations: installation/codegen owns their formatting, and these files are already Git-ignored.

Application `DATABASE_URL` continues to point at Neon, now through a Node PostgreSQL pool supporting actual transactions. Request pools hold at most two connections, release idle sockets after one second, bound connection age to 30 seconds and allow process exit when idle. A persistent worker uses `createDb(config, { persistent: true })`, owns at most five connections and must call `db.$client.end()` on shutdown; its separate credentials/config arrive with the worker ticket. `DATABASE_MIGRATION_URL`, when configured, is the direct/non-pooler Neon connection used by Drizzle migrations; absent it, the existing `DATABASE_URL` convention remains. Generate migrations with `pnpm db:generate` (no environment loading); run migrations explicitly with `pnpm db:migrate` only against the intended database. The initial migration includes the starter auth tables for a fresh database. For an already migrated starter database, reconcile/baseline the existing auth tables before applying the initial migration; do not run this initial DDL blindly on an existing application database.

Every project write runs `requireProject(tx, ownerId, projectId, operation)` inside its transaction. The guard locks the project, resolves ownership, rejects archived writes and denies deleting projects; future manual/API/worker publication must call the same guard. Reads use the guard without a lock. Unarchive is the only archived mutation allowed. `assertDiscoveryBrief` requires a saved title and topic before later discovery; incomplete briefs otherwise remain valid, and unknown resources are explicit strings.

Deletion commits a tombstone before cleanup, so cleanup failure cannot reopen access. `createProjectCleanupRegistry(additionalHooks)` (injected as application service `projectCleanup`) registers idempotent artifact cleanup inside a transaction; this slice registers brief revisions only. `retryProjectCleanup(db, registry)` is the operator/worker retry contract; tombstones remain and private brief/title content is removed. Later artifact slices must register their private relationship/text/object cleanup and cancellation before enabling their data. No backup/provider erasure promise is made by this local cleanup contract.
